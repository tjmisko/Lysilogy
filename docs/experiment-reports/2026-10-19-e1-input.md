# Extraction spike, E1 input: raw vs markdown+priors

Status: 2026-10-19. Baseline
[E0](2026-10-19-core-only-barebones.md). Raw records, ledger and metrics:
`eval/spike/runs/e1-raw-2026-10-19/` and
`eval/spike/runs/e1-markdown-2026-10-19/`.

## Summary

Two runs over the same 20 papers, config-driven combined core call, effort
`low`, passes 2, self-check full, repair model, only the input changed. Raw wins
on every axis and costs less; markdown+priors did not raise sections.

The comparison is **not a clean input verdict** yet. The config plan runner caps
the core call at `FEATURE_MAX_TOKENS` (24,576) instead of `CORE_MAX_TOKENS`
(65,536), and unpinned provider routing landed the expensive Together host on
the core call. Both are fixed or explained below; the input question is
re-opened until the cap is corrected.

## What ran

Raw and markdown+priors configs, `--provider` dropped (DeepSeek serves no
endpoint for this model). 20 papers, `--paper-budget 0.20`, 4 at a time.

## Results

| | E0 barebones | E1 raw | E1 markdown+priors |
| --- | --- | --- | --- |
| completed | 19/20 | 16/20 | 16/20 |
| title exact | 19/20 .95 | 16/20 .80 | 15/20 .75 |
| authors exact | 19/20 .95 | 15/20 .75 | 14/20 .70 |
| abstract | 19/20 .95 | 16/20 .80 | 16/20 .80 |
| sections coverage | 0.800 | 0.782 | 0.707 |
| papers <95% | 7 | 7 | 7 |
| malformed units | 8 | 0 | 0 |
| refs / cites / rels | 615 / 415 / 169 | 594 / 434 / 138 | 521 / 369 / 113 |
| cost | $0.3612 | $0.7369 | $0.8572 |

Stage spend (raw): core 77.3%, self-check 17.0%, repair 5.7%. Markdown: core
65.9%, self-check 30.2%, repair 3.9%.

## Confounds

1. **Plan output cap.** `run_plan` calls the core call with `FEATURE_MAX_TOKENS`
   (24,576), while the built-in core pass uses `CORE_MAX_TOKENS` (65,536). All
   three length failures stopped at exactly 24,576 completion tokens. E0
   completed 19/20 at the higher cap.
2. **Provider routing is uncontrolled.** The unpinned core call landed on
   Together at roughly 5–6× the Relace rate that served E0's pass 1, so E1's
   core is 4× E0's core per token. The cost delta is routing, not the config.
3. **Identity misses are the failures.** The raw title and abstract misses are
   exactly the 4 failed core calls. Conditioned on success raw is 16/16 title,
   16/16 abstract, 15/16 authors.

## What we learned

- Correction validation works: malformed section units 8 → 0.
- Identity is effectively exact once a call completes; the input format does not
  move it. The remaining author misses are text-layer artifacts
  (`B ROSSARD`, `Tworzyd lo`) and one markdown transcription slip, not prompt
  problems.
- Sections is the only field that does not saturate: ~0.78 coverage, 7/20 below
  95% in both arms, stable across input.
- Raw is at least as good as markdown+priors on sections and the graph, and
  cheaper. Markdown+priors did not earn its higher cost.
- Provider routing is a first-order cost and reliability lever that was left
  free.

## Next

1. Give core-carrying plan calls `CORE_MAX_TOKENS`, and make the output cap a
   per-call config value (axis D). Re-run E1 for a clean input verdict.
2. Pin the provider for any comparison. DeepSeek cannot serve this model, so use
   a real host.
3. Then attack sections, the only unsatisfied field: combined@low (control),
   combined@medium, and fanout with a dedicated high-effort sections call, on
   the hard subset, validating the winner on all 20.

## Deferred: loose identity matching

Do not build until an acquisition matcher exists.

- Compare on a loose key, never on the stored artifact. `layout::canonical_chars`
  preserves verbatim quotes, so use a second key: NFKD, casefold (not `lower`),
  strip combining marks, expand `ﬁ ﬂ ﬀ`, drop punctuation and whitespace,
  transliterate `ł ø đ ð þ æ œ ɡ`.
- **Authors are a set, not a sequence.** Identity should tolerate order
  variations from other sources; keep the printed order in the artifact as data,
  but match per name with normalized edit distance or a token ratio.
- Title by token-set ratio, not raw character distance.
- One shared implementation with a version tag, so scorer and matcher cannot
  drift.
