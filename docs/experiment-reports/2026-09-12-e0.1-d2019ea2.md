# E0.1 measured synthetic 10k baseline

The complete default `python3 scripts/bench/run.py` run succeeded with 10,000 deterministic
PDFs and 10,000 real persisted extraction artifacts. It establishes the E0.3/E0.4 performance
baselines: populated rescans and both home measurements miss their unchanged targets. Existing
open issues [#21](https://github.com/tjmisko/Lysilogy/issues/21) and
[#22](https://github.com/tjmisko/Lysilogy/issues/22), under epic E0, now carry the measured gaps
and next approaches. This completes the measurement required by #19; performance improvements
remain Phase B work.

## Measured gaps and next approaches

O25 is 7.75 times its limit. The 1.34-second discovered-only result compared with the
15.50-second populated result points to saved-artifact loading as the first cost to investigate;
this comparison is evidence for an approach, not a profiler attribution. #21 will cache unchanged
extraction metadata or use a compact catalog projection keyed by canonical identity and verified
source stamps. It must preserve additions/deletions/moves, duplicate/replacement handling, and
artifact invalidation, then measure actual populated scans before and after.

O26 render is 3.51 times its limit; search p95 is 1.09 times its limit. The measured 10,000-card
DOM supports the planned #22 approach: viewport virtualization plus paginated server filtering,
sorting, and search. It must retain keyboard navigation across windows/pages, selected-card
restoration, bounded previews, and the existing independently checked input-to-paint contract.
Both issues remain open under E0. No target, hard gate, or baseline was weakened; #19 records the
existing implementation as the baseline rather than moving the Phase B optimizations into A1.
